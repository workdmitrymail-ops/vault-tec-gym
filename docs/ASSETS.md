# MILO 2.0 · план генерации ассетов и промпты

Версия от 22 сентября 2026, обновлена после появления референсного листа маскота и первой поставки файлов. Название приложения: VAULT-TEC GYM. Основание: `claude/milo_v2_spec.md` (макет, токены, слоты) и `claude/milo_v2_nano_banana_plan.md` (общий план визуала).

Макет из 25 артбордов согласован. Осталось сгенерировать 26 файлов: маскот в семи кадрах, мышечная карта из двух баз и восемнадцати масок, иконка приложения.

## 1. Условия работы

| Параметр | Значение |
|---|---|
| Инструмент | приложение Gemini, подписка Google AI Pro |
| Модели | Nano Banana 2 по умолчанию, Nano Banana Pro через повторную генерацию для финальных кадров |
| Лимит | около 100 изображений в день, Google указывает, что лимиты могут меняться |
| Форматы кадра | 1:1 для маскота и иконки, 2:3 для мышечной карты |
| Разрешение | 2K достаточно |
| Передача Claude | файлы прикладываются в чат партиями или через подключённую папку |

Перед началом выключите видимый водяной знак в настройках Gemini (Media Watermark). Прозрачного фона Nano Banana не делает: все ассеты генерируются на ровном однотонном фоне, фон удаляется на этапе программирования.

## 3. Группа A. Маскот, 7 генераций

Внешность персонажа задаётся референсным листом, который пользователь подготовил отдельно. Лист прикладывается к каждой генерации группы A. Начиная с A2 дополнительно прикладывается утверждённый файл A1.

Текстовое описание персонажа больше не нужно: лист точнее слов. Но в промпте обязателен запрет на копирование самого листа, иначе модель воспроизводит его композицию с несколькими ракурсами и подписями.

Подписи палитры на листе неточные (красный подписан как жёлтый, два одинаковых значения подписаны как разные тона кожи), поэтому в промпте нельзя ссылаться на названия цветов, только на то, что видно.

На листе две комплекции: обычная в основных видах и накачанная в отдельном кадре. Во всех семи генерациях указывается одна и та же, иначе фигура будет меняться от кадра к кадру.

### Общий блок A

Повторяется в каждом промпте группы без изменений.

```
Персонаж строго с приложенного референсного листа: внешность, пропорции, причёска,
мимика, одежда, обувь и цвета точно как там. Художественная подача тоже с листа:
объёмная светотень, чистые сглаженные контуры, тот же уровень детализации.
Телосложение как в основных видах в верхнем ряду листа.

Не воспроизводи сам лист: в кадре одна фигура, без нескольких ракурсов, без панелей,
без подписей, стрелок, выносок, образцов цвета и любого текста.

Кадр квадратный. Фон ровный однотонный #1E1E1E, без градиента, без виньетки,
без тени под фигурой. Персонаж не касается краёв кадра, пустое поле не меньше
8 процентов с каждой стороны. Освещение ровное фронтальное, вид прямо, без перспективы.
```

С A2 к блоку добавляется строка:

```
Поза и кадрирование новые, всё остальное без изменений относительно приложенных изображений.
```

### Приёмка группы A

1. Одинаковая внешность и одна и та же комплекция на всех семи кадрах.
2. Фон ровный, одного цвета, без градиента.
3. Персонаж не обрезан краями кадра.
4. Текста, подписей и панелей с листа в кадре нет, фигура одна.
5. A1 читается при уменьшении до 40 px.

## 4. Группа B. Мышечная карта, 20 генераций

Логика: сначала две базы без подсветки, затем маски. Маска это правка базы, где одна зона залита чистым цветом, а всё остальное не изменилось. Контуры зон извлекаются в коде по разнице между маской и базой. Пятнадцать готовых вариантов подсветки не подойдут: фигура в каждом будет немного отличаться, и карта будет дёргаться при переключении.

### B1 и B2, базы

Каждая генерируется в своём чате, формат 2:3, разрешение 2K. В квадратных скобках подставляется вид.

```
Анатомическая иллюстрация мускулатуры мужской фигуры, вид [спереди / сзади],
фигура целиком, строго по центру кадра, симметричная стойка,
руки слегка отведены от корпуса, ладони развёрнуты вперёд,
чтобы были видны широчайшие, трицепс и предплечья.
Фигура занимает 90 процентов высоты кадра, формат 2:3.

Подача: плоская иллюстрация, спокойная светлая заливка тела одним цветом #D8DCD4,
тонкие контуры мышечных групп цветом #6E7A6E толщиной 2 px, все группы читаются раздельно.
Без подсветки, без выделения отдельных мышц, без градиентов, без свечения, без теней.
Голова обозначена обобщённо, без черт лица.

Фон ровный однотонный #0000FF, без градиента, без тени под фигурой.
Без текста, без подписей, без стрелок, без сетки, без рамки.
```

Синий `#0000FF` здесь технический фон, а не цвет интерфейса: по нему `tools/build_muscle_map.py` отделяет силуэт от фона (порог `BG_THRESHOLD`), в `assets/map` фон уже прозрачный, к палитре приложения он отношения не имеет.

Файлы: B1 `base_front.png`, B2 `base_back.png`.

### B3…B20, маски

Каждая маска делается правкой базы в том же чате, где эта база сгенерирована.

ровной плоской светло зелёной заливкой, без градиента, без тени, с чёткими краями.
Всё остальное оставь абсолютно без изменений: фигура, поза, положение, размер,
контуры, цвета, фон. Ничего не двигай и не перерисовывай.

## 11. Изменения, внесённые при генерации, 22 сентября 2026

1. **Цвет подсветки зон зелёный, не красный.** В промптах масок стоял чистый #FF0000, но при генерации пользователь перешёл на светло зелёную заливку со свечением поверх серой фигуры. Все 14 масок сделаны именно так. Это зафиксированное решение, переделывать маски не нужно.

   Следствие для обработки: зона извлекается по приросту зелёности относительно базы, то есть по разнице величины G минус среднее из R и B между маской и базой. Порог, сжатие края и заливка промежутков между штрихами заданы в `tools/build_muscle_map.py` версии 2 константами GREEN_GAIN и ERODE.

2. **Набор зон сокращён до 14.** Три пучка дельт объединены в одну зону на каждом виде, трапеция и икры на виде спереди исключены.

3. **Иконка приложения не соответствует заданию C1.** Вместо светлого фона и одного простого символа сгенерирована подробная сцена с надписями. В размере 60 px не читается. Помечено к перегенерации, на сборку не влияет.

4. **Маскот весит около 4.9 МБ в семи файлах по 1024 px.** Показывается максимум в 200 px, поэтому при сборке файлы уменьшаются до 600 px по длинной стороне.
